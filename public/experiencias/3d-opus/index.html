Primer giro · plano Google

Para Google, eres un sub con permisos.

chrome.identity abre un portal. Al cruzarlo, lo que era pared se vuelve suelo. Google decide quién eres y qué podrá hacer Nocturne en YouTube. Te entrega una pieza azul, el code, y la devuelve por el portal (redirect).

Redirect · plano del usuario

El code pasa por tus manos.

Chrome recibe el redirect de Google y lo entrega a Nocturne por un portal dorado. La extensión solo transporta el code: no puede canjearlo ni abrir nada con él.

Segundo giro · plano Nocturne

Lambda Auth: el puente de confianza.

El code llega por el portal dorado y encaja en Lambda Auth, que lo canjea con Google. El refresh token pasa por KMS y sale cifrado hacia DynamoDB. Con el secreto de SSM, Nocturne forja su propia pieza dorada: el JWT.

Vuelta a casa · plano del usuario

Ahora llevas una pieza que solo Nocturne reconoce.

El JWT cruza el portal y encaja en storage.local. El refresh token nunca llega aquí: se quedó, cifrado, en el mundo de Nocturne.

De nuevo en Nocturne · acceso a la API

Para la API, eres un Bearer JWT.

Cada POST /jobs o GET /status lleva la pieza dorada. Upload y Status verifican su forma (firma y vencimiento) y usan su sub para abrir solo tus trabajos: USER#sub / JOB#id.

El momento puzzle · plano Google

El JWT no abre YouTube.

Arrastra las piezas hacia la cerradura de YouTube API para comprobarlo: el JWT dorado rebota; solo el access token encaja.

Arrastra una pieza hasta YouTube API.

De noche · plano Nocturne (sin usuario)

El usuario se fue. El Worker sigue solo.

Un mensaje SQS despierta al Worker con jobId y userId. No hay navegador ni JWT. Lee PROFILE, pasa la pieza cifrada por KMS y recupera el refresh token.

De noche · plano Google

Acceso renovado en silencio.

El Worker canjea el refresh token en Google, obtiene un access token temporal y por fin abre YouTube API.

Las grietas en main · plano Nocturne

Dos puntos frágiles en la frontera.

1 · Credencial no garantizada: si Google omite el refresh token, Auth emite el JWT igualmente y no actualiza el perfil. Si ya había un refresh token en DynamoDB, se conserva; si no lo había —o el anterior dejó de ser válido—, el Worker no podrá autenticarse con Google.
2 · Portal sin guardián: API Gateway no declara JWT authorizer; la validación vive dentro de Upload y Status.
